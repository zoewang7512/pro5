# 畫面規格

## Metadata

- 功能：多位設計師（`ai/artifacts/多位設計師/feature-spec.md`）
- 畫面：後台設計師管理列表（`/admin/designers`）＋設計師編輯頁（`/admin/designers/[id]`）
- 狀態：mockup 已核准（Variant A，使用者 2026-10-21，見 `mockup-decision-後台設計師管理.md`）。
  下方描述 A／B 差異的段落保留作為追溯，實作以 A 為準：表格列表、上下箭頭排序、四頁籤編輯頁、
  新增設計師直接進空白編輯頁。

## 目的

讓店長建立和維護每位設計師的公開資料（頭像、名稱、簡介、專長、IG）、提供哪些服務、作品集與
請假日，並控制設計師在前台的顯示順序與啟用狀態。

## 版面配置

- 主要區域：
  - 列表頁：所有設計師（含停用中），顯示頭像、名字、專長、提供服務數、狀態，以及編輯、停用、
    重新啟用操作。Variant A 是表格，Variant B 是卡片牆。
  - 編輯頁：四個區塊「基本資料／提供服務／作品集／請假」。Variant A 用頁籤，Variant B 用單頁
    捲動的四張卡片加右側錨點。
- 次要區域：停用確認對話框、請假日受影響預約警告對話框、（Variant B）新增設計師 Modal。
- 導覽：Sidebar 新增「設計師」項目，放在「預約」之後（`AdminShell.tsx` 的導覽清單），用手繪
  SVG 圖示，比照 TASK-064 慣例。編輯頁上方有麵包屑「設計師 ／ ○○」可以回列表。
- 動作：新增設計師、編輯、停用、重新啟用、調整順序、儲存基本資料、開關服務、上傳／刪除作品、
  標記／取消請假。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設 | 列表依 `sort_order` 排序，停用中的設計師用較淡的樣式加「已停用」徽章 | — | 螢幕截圖 |
| 載入中 | Skeleton 占位；「新增設計師」按鈕停用 | — | 螢幕截圖 |
| 空狀態 | 升級後至少有預設設計師，理論上不會出現；仍需要提供空狀態 | 「還沒有設計師，新增第一位設計師開始接受預約。」 | 單元測試 |
| 錯誤 | 讀取失敗顯示 error Alert；儲存失敗用既有 Toast 顯示通用訊息，不外洩原始錯誤 | 「無法載入設計師資料，請重新整理頁面再試一次。」 | 螢幕截圖 |
| 停用 | 停用中的設計師仍可以編輯；操作欄顯示「重新啟用」 | — | 螢幕截圖 |
| 權限不足 | 沿用 `app/admin/layout.tsx` 的既有檢查（未登入、未達 aal2、非 admin 都進不來），本頁不另外處理 | — | 既有整合測試 |
| 行動裝置版 | 後台以桌面為主（既有非目標），不另外設計，只確認 768px 寬度不破版 | — | 螢幕截圖 |
| 基本資料驗證錯誤 | 欄位下方顯示錯誤，阻擋儲存 | 名稱：「請輸入 1～30 字的名稱」；IG：「只能使用英文、數字、底線和句點」；專長：「最多 5 個標籤」「每個標籤 12 字以內」「標籤不能重複」；簡介：「200 字以內」 | 單元測試 |
| 頭像上傳 | 重用 `ImageUploadField` 的四態（預設／上傳中／預覽／錯誤） | 沿用既有元件文案 | 螢幕截圖 |
| 作品集上傳中 | 新格子顯示 spinner | — | 螢幕截圖 |
| 作品集達上限 | 上傳格停用 | 「已達 12 張上限，請先刪除舊作品」 | 螢幕截圖 |
| 作品集空狀態 | 只顯示上傳格 | 「還沒有作品，上傳第一張吧」 | 螢幕截圖 |
| 停用確認 | 對話框顯示未來有效預約筆數；停用最後一位啟用中的設計師時，另外警告 | 「停用後前台將沒有任何可預約的設計師」 | 螢幕截圖 |
| 請假受影響預約 | 對話框列出當天該設計師的預約（時間、顧客、服務），店長確認後才寫入 | 「這些預約不會自動取消，也不會通知顧客，請記得另外處理。」 | 螢幕截圖 |

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 新增設計師 | A：進入空白編輯頁；B：Modal 輸入名稱後建立並進入編輯頁 | 建立設計師（預設啟用、不提供任何服務） | 名稱驗證錯誤；寫入失敗 Toast |
| 儲存基本資料 | 按「儲存」 | 驗證後寫入，成功 Toast | 驗證錯誤；寫入失敗 Toast |
| 開關服務 | 點 Switch | 即時寫入，失敗時 Switch 回復原狀並顯示 Toast | 寫入失敗 |
| 上傳作品 | 點上傳格或拖放 | 檢查類型、大小、張數上限，上傳後顯示在最前面 | 類型或大小錯誤、達上限、上傳失敗 |
| 刪除作品 | 點作品右上角 × | 二次確認後刪除 | 刪除失敗 Toast |
| 標記請假 | 點月曆未來日期 | 沒有受影響預約時直接寫入；有的話先跳警告 | 過去日期不能點（沿用 `MonthPicker`） |
| 取消請假 | 點已標記日期，或清單的「移除」 | 直接移除，不另外警告（比照公休日） | 寫入失敗 Toast |
| 停用／重新啟用 | 點操作 | 停用有二次確認，重新啟用直接執行 | 寫入失敗 Toast |
| 調整順序 | A：上下箭頭；B：拖曳把手 | 寫入 `sort_order` | 寫入失敗時還原順序 |

## 設計系統對照

- 用到的既有 design token：grey 全階、primary 50/500/700、success-light（啟用中徽章）、
  warning／warning-light（請假日、受影響預約警告，沿用公休日的配色語意）、danger（停用按鈕、
  驗證錯誤）、info-light（公開資料提示）、radius.sm／md、elevation1／2、type scale、字重。
- 用到的既有元件：Sidebar、Table（A）、Card（B）、Button、Input、Switch、Chip、ConfirmDialog
  （含 `children` 插槽，列受影響預約）、ImageUploadField（頭像）、MonthPicker（請假日）、
  Toast/Alert、Skeleton、FormSection。
- 本畫面新做的元件（核准變體後實作時登記回 inventory）：
  - `TagInput`：專長標籤輸入（Enter 新增、× 刪除、計數器）。用 MUI `Autocomplete` 的
    `multiple` 加 `freeSolo` 模式即可，不另做 wrapper；只要在 inventory 登記用法。
  - `PortfolioManager`：作品集後台格狀管理（上傳格、刪除、上傳中、達上限），以既有
    `ImageUploadField` 的驗證邏輯與 token 製作。
  - Variant B 另需拖曳排序，要評估新增拖曳套件的成本，或改用上下箭頭。

## 視覺驗收標準

- 文字在手機版與桌面版都不會被截斷。
- 主要動作清楚明確：列表頁的「新增設計師」、編輯頁的「儲存」是 primary 按鈕。
- 錯誤與空狀態明確呈現。
- **色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。**
- **重複使用元件庫 inventory 裡的既有元件；任何新做的元件都依既有 token 與風格製作，且已登記回 inventory。**
- 公開資料提示要出現在基本資料區塊，讓店長知道這些內容會在前台公開。
