# 畫面規格

## Metadata

- 功能：營業時間與可預約時段管理（第一批次「設定每週固定營業時間」已實作；本次修訂新增
  第二批次「設定公休日／特殊假期」的「特殊公休日」區塊，見下方標示「（第二批次新增）」
  的段落）
- 畫面：營業時間設定（`/admin/business-hours`）
- 狀態：每週固定營業時間區塊 mockup 已核准並實作（變體 A 表格式一次編輯，見
  [`mockup-decision-營業時間設定.md`](mockup-decision-營業時間設定.md)）；特殊公休日區塊
  mockup 已核准（變體 B 小型月曆選取器＋清單，見
  [`mockup-decision-特殊公休日.md`](mockup-decision-特殊公休日.md)），待實作，需先新做並
  登記月曆選取器元件回 S4 inventory

## 目的

讓設計師檢視並編輯每週固定營業時間（週一至週日各自的開店/打烊時間、是否公休），取代目前
只能透過 seed script 或直接改資料庫才能調整 `business_hours` 表的現況；同時作為
`isClosedWeekday()` 技術債的資料來源修正起點——本畫面編輯完成後，後台週曆的公休日顯示會
改查 `business_hours.is_closed`。（第二批次新增）同一頁再新增「特殊公休日」區塊，讓設計師
標記特定單一日期（例如國定假日）整天公休，取代目前只能透過資料庫直接寫入 `closed_dates`
的現況。

## 版面配置

- 主要區域：七天營業時間清單（每天：星期標籤、公休切換、開店/打烊時間輸入）。
- 次要區域：頁首說明文字（一行 hint）；送出前的受影響預約警告 Modal（條件觸發，非常駐）。
- 導覽：既有 Sidebar，「營業時間」項目從 `disabled` 改為可點擊並標記為 active。
- 動作：「儲存變更」（主要）；若變更會影響既有預約，中途插入「仍要儲存／再想想」二次確認。
- （第二批次新增）七天清單下方新增「特殊公休日」區塊：標題＋說明文字、新增控制項（依選定
  變體為日期輸入＋按鈕，或小型月曆選取器）、已設定日期清單（每筆可個別移除）。新增時若有
  受影響預約，插入獨立的「仍要新增／再想想」二次確認 Modal（與每週固定營業時間的警告
  Modal 為同一元件模式、不同文案內容，兩者互不干擾，不會同時觸發）。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設 | 顯示七天目前的 `business_hours` 設定（開店/打烊時間或「公休」） | 不適用（`business_hours` 固定 7 列，seed 後恆有資料，不會是空表） | 螢幕截圖 |
| 載入中 | 顯示骨架屏（比照既有 `Skeleton` 元件） | 無 | 螢幕截圖 |
| 錯誤 | 查詢 `business_hours` 失敗時顯示錯誤訊息＋重試 | 「無法載入營業時間設定，請重新整理再試一次」 | 螢幕截圖 |
| 停用 | 送出中：所有欄位與按鈕鎖定，主按鈕顯示載入中；公休切換開啟時，同一天的時間欄位停用（比照既有 `disabled` 樣式） | 無 | 螢幕截圖 |
| 權限不足 | 非 `is_admin()` 或未登入直接訪問 `/admin/business-hours` | 沿用既有 `/admin` 頁面的既有導回 `/login` 行為，不另立新邏輯 | 手動驗證 |
| 行動裝置版 | 非本階段重點，沿用既有後台「桌面/平板優先」決策（比照「預約管理後台」Epic） | 不適用 | 不適用 |

補充：受影響預約警告是一個條件觸發的確認態（送出時偵測到衝突才出現），不是清單裡的「空狀態」，
以「互動」章節的動作流程呈現。

### 特殊公休日區塊狀態（第二批次新增）

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設（已有設定） | 顯示已設定的特殊公休日清單，每筆可移除；新增控制項可用 | 不適用 | 螢幕截圖 |
| 空狀態（尚無設定） | 清單區域顯示提示文案，不影響新增控制項可用性 | 「尚無設定的特殊公休日」 | 螢幕截圖 |
| 新增中／新增失敗 | 新增按鈕顯示載入中並鎖定；失敗時顯示通用錯誤 Toast，不外洩原始 Postgres 錯誤內容 | 「操作失敗，請稍後再試」（沿用既有 Toast 錯誤文案慣例） | 螢幕截圖 |
| 驗證錯誤 | 選擇過去日期時，新增按鈕停用並顯示行內錯誤 | 「日期須為今天或未來」 | 螢幕截圖 |
| 受影響預約警告 | 新增會影響未來既有預約時，顯示二次確認 Modal，列出受影響預約（日期/時段/顧客姓名） | 「◯◯（週◯）目前有 N 筆未來預約會受影響：」 | 螢幕截圖 |
| 移除 | 點擊清單裡的移除按鈕，不顯示警告，直接刪除該筆 | 無 | 螢幕截圖 |

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 切換某天為公休 | 點擊該天的公休開關 | 該天的開店/打烊時間欄位清空並鎖定 | 無 |
| 切換某天恢復營業 | 對已公休的天關閉公休開關 | 時間欄位解鎖，需重新填入合法時間才能送出 | 欄位為空或打烊未晚於開店時，送出被擋 |
| 編輯開店/打烊時間 | 修改時間輸入欄位 | 即時前端驗證打烊須晚於開店 | 不合法時該列顯示行內錯誤，送出按鈕保持可點但送出會被前端擋下並聚焦到第一個錯誤列 |
| 送出「儲存變更」 | 點擊主要按鈕，且目前無前端驗證錯誤 | 若無受影響預約：直接呼叫 authenticated 直接 update 七列 `business_hours`，成功後顯示成功 Toast、資料重新整理 | 若有受影響預約：改為顯示警告 Modal，需二次確認；資料庫寫入失敗顯示通用錯誤 Toast，不外洩原始 Postgres 錯誤內容 |
| 警告 Modal：仍要儲存 | 已顯示受影響預約清單後點擊 | 送出實際的 `business_hours` 更新，成功後關閉 Modal 並顯示成功 Toast | 同上「資料庫寫入失敗」情境 |
| 警告 Modal：再想想 | 已顯示受影響預約清單後點擊 | 關閉 Modal，不送出任何變更，欄位維持使用者目前編輯的內容（不重置） | 無 |
| （第二批次新增）新增特殊公休日 | 選擇日期（依變體：輸入框選日或月曆點選）並確認新增 | 若無受影響預約：直接寫入 `closed_dates`，成功後清單即時反映；若過去日期：前端擋下不送出 | 若有受影響預約：顯示警告 Modal，需二次確認；寫入失敗顯示通用錯誤 Toast |
| （第二批次新增）警告 Modal：仍要新增 | 已顯示受影響預約清單後點擊 | 送出實際的 `closed_dates` 寫入，成功後關閉 Modal 並更新清單 | 同上「寫入失敗」情境 |
| （第二批次新增）警告 Modal：再想想 | 已顯示受影響預約清單後點擊 | 關閉 Modal，不寫入，選擇的日期維持在新增控制項中（不清空，方便使用者確認後再試一次） | 無 |
| （第二批次新增）移除特殊公休日 | 點擊清單裡某筆的移除按鈕 | 直接刪除該筆，不顯示警告（移除只會讓該天恢復成每週固定營業時間） | 刪除失敗顯示通用錯誤 Toast |

## 設計系統對照

- 用到的既有 design token：`color.primary`（主按鈕、公休開關開啟色）、`grey` 色階（次要文字、
  停用欄位背景、分隔線）、`warning.light`（受影響預約列底色）、`radius.sm`（輸入框/按鈕）、
  `radius.md`（卡片/Modal）、`elevation1`／`elevation2` 陰影、`space` 4 的倍數間距、
  type scale（`xs`/`sm`/`base`/`lg`）。
- 用到的既有元件：`Sidebar`（既有導覽，啟用「營業時間」連結）、`TextField`（`type="time"`
  作為時間輸入，沿用既有 Input 元件，不需要另做時間選擇器）、`Table`（若選表格式變體）、
  `Card`（若選卡片式變體）、`ConfirmDialog` 的互動模式（受影響預約警告，比照既有取消預約
  二次確認的「主要操作／再想想」按鈕配置，但內容改為清單而非純文字，需要擴充或另建一個
  類似元件）、`ToastProvider`（成功/錯誤提示）、`Skeleton`（載入中）。
- 本畫面新做的元件：**Switch（開關）**——目前 S4 inventory 只有 `Checkbox`／`Radio`，沒有
  「立即生效的二元開關」語意元件；公休切換屬於「開/關某個持續狀態」而非「勾選一個選項」，
  採用 MUI `Switch` 較符合慣例。做法：直接使用 `@mui/material/Switch`，不需要額外
  theme override（MUI 元件預設即讀取 `theme.palette.primary`，比照 `Checkbox`／`Radio`
  當初的做法），完成後登記回 `design-system.md` 的 S4 元件庫 inventory。
- （第二批次新增）特殊公休日區塊重用的既有 token／元件：`grey`／`primary`／`warning`／
  `info` 色階、`radius.sm`/`md`、`elevation1`/`elevation2`、4 的倍數間距、type scale；
  `ConfirmDialog`（受影響預約警告，沿用既有 children 插槽模式）、`Button`、`Card`／`Box`
  拼版面容器。
- （第二批次新增）本畫面新做的元件：**月曆選取器（Month Picker）**——已核准變體 B（見
  [`mockup-decision-特殊公休日.md`](mockup-decision-特殊公休日.md)），S4 inventory 目前
  只有週檢視的 `WeekCalendar`（頁面專用非跨頁共用），沒有月檢視、可點選標記的元件。需要
  依既有色彩/圓角/陰影風格新做（今天標示比照 `WeekCalendar` 的 `outline: primary.main`
  做法、已標記日期用 `warning.light` 背景＋`warning` 文字色，比照受影響預約警告列的既有
  配色慣例），涵蓋跨月導覽、今天標示、過去日期停用（不可點選）等狀態，完成後登記回
  `design-system.md` 的 S4 元件庫 inventory。

## 視覺驗收標準

- 文字在手機版與桌面版都不會被截斷（本階段桌面/平板優先，仍需基本自適應不破版）。
- 主要動作（儲存變更）清楚明確，且在有未儲存變更時才可點擊（避免誤觸空按鈕造成困惑）。
- 錯誤（打烊早於開店）與載入中狀態明確呈現，不與正常狀態混淆。
- 色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的
  一次性數值。
- 重複使用元件庫 inventory 裡的既有元件；新做的 `Switch` 元件依既有 token 與風格製作，
  且完成後登記回 inventory。
