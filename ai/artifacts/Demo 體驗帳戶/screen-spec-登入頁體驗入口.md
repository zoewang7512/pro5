# 畫面規格

## Metadata

- 功能：Demo 體驗帳戶（故事 S2「登入頁體驗入口」）
- 畫面：登入頁 `/login` 的「體驗帳號」入口
- 狀態：mockup 已核准（變體 A，一鍵進入版；最終狀態見 `mockups/demo-login-entry-final.html`）

## 目的

讓第一次來的面試官在登入頁就知道有體驗帳號，按一下就直接進入後台，不需要輸入或看到任何帳密；進入後立即看到說明視窗，知道自己在體驗帳號。

> 2026-10-30 更新：原本「只填入欄位、不自動送出」改為「一鍵直接進入」，下表與互動以此為準。

## 版面配置

- 主要區域：既有置中登入卡片（Email、密碼、登入、忘記密碼），不改動。
- 次要區域：體驗帳號入口（卡片內下方，「或」分隔線後的平面背景說明區，一句說明加 outlined 按鈕）。
- 導覽：按下並成功後離開 `/login`，導向後台，並顯示說明視窗。
- 動作：「進入體驗帳號」，由伺服器端登入並建立 session，**不需要使用者輸入任何帳密**。

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 進入體驗帳號 | 點入口按鈕 | 呼叫伺服器端一鍵進入端點，成功後導向後台並設定「顯示說明視窗」旗標；不送出任何帳密欄位 | 失敗顯示錯誤 Alert 並可重試；設定缺漏時入口不渲染，不會出現壞掉的按鈕 |
| 一般登入 | 使用者填 Email 與密碼按「登入」 | 走既有登入與限流流程，不受入口影響 | 沿用既有 |
| 重複點擊 | 載入中再次點擊 | 按鈕已停用，不重複送出 | — |
| 忘記密碼 | 在忘記密碼表單輸入 Demo Email 並送出 | 呼叫 Supabase，被資料庫觸發器擋下（不寄信）；前端顯示通用錯誤加「若您是要體驗，請回登入頁…」引導與「回登入頁」按鈕（TASK-119，方案 A；不是前端攔截，也不比對信箱） | 其他任何失敗（網路、限流）在 Demo 入口開啟時也會看到同一行引導，屬方案 A 的已知取捨；直接呼叫 API 時信不會寄出（TASK-100） |

## 設計系統對照

- 用到的既有 design token：grey.100／grey.300／grey.700（入口區塊平面背景、分隔線、說明文字）、primary.500／primary.700（按鈕、連結）、primary.50（已填入欄位淡底）、info／success（Alert 底色）、radius.sm／md、shadow elevation1（既有登入卡片）、type scale 11／12／13／16／20、字重 400／500／600／700、spacing scale（4 的倍數）。
- 用到的既有元件：Card、TextField、Button（contained／outlined，含 `loading`）、Alert（info／error）、Divider、Link。
- 本畫面新做的元件：無。

## 視覺驗收標準

- 文字在手機版與桌面版都不會被截斷。
- 主要動作清楚明確：登入仍是唯一 contained 主按鈕（A），入口按鈕為 outlined，不搶主動作。
- 錯誤與空狀態明確呈現。
- 色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。
- 重複使用元件庫 inventory 裡的既有元件；沒有新做元件。
- 亮色與暗色模式皆可讀（暗色由 theme 自動帶入，實作後各截圖一次）。
