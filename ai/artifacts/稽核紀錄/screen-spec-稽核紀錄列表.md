# 畫面規格

## Metadata

- 功能：稽核紀錄（簡版，`ai/artifacts/稽核紀錄/feature-spec.md`「列表」）
- 畫面：稽核紀錄列表（`/admin/audit-log`）
- 狀態：mockup 已核准（變體 A，使用者 2026-10-24，見 `mockup-decision-稽核紀錄列表.md`）。實作以 A 為準：四欄表格＋Chip 篩選；窄視窗表格橫向捲動（最小寬度 720px）。B／C 的描述保留作追溯。

## 目的

讓店長在發現「前台突然沒時段」「顧客說預約被改」時，能依時間倒序回看店裡發生過哪些後台操作、改了什麼（前後值），並依類別（預約／設定）縮小範圍。**唯讀**：不能編輯、刪除、匯出。

## 版面配置

- 主要區域：紀錄列表。每筆四項資訊（皆由 `describeAuditEntry` 與 `created_at` 組成，純文字）：
  - 發生時間（Asia/Taipei，`M/D HH:mm`）。
  - 事件（中文名稱，例如「取消預約」）。
  - 對象摘要（例如「剪髮・林小美・10/25 15:00–16:00」；沒有對象資訊時以「—」表示）。
  - 前後差異（0～N 行白話，例如「最短提前預約時間：2 小時 → 720 小時」；沒有差異時以「—」表示）。
- 次要區域：頁首（標題「稽核紀錄」＋一行說明：「記錄後台的預約與設定操作，最新的在最上面。僅供查看，無法修改或刪除。」）、類別篩選（全部／預約／設定）、列表底部「載入更多」。
- 導覽：Sidebar 新增「稽核紀錄」，**放在最後一項**（「帳號設定」之後），用手繪 SVG 圖示（比照 TASK-064 慣例）；`isNavItemActive` 既有規則已涵蓋。
- 動作：切換類別、載入更多、（錯誤時）重試。沒有其他寫入動作。
- 不顯示：操作者（單一店長，欄位保留）、總筆數、顧客資訊。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設 | 以 `id` 倒序顯示第一頁 50 筆；底部有下一頁時顯示「載入更多」，沒有時顯示「已顯示全部紀錄」（至少有一頁資料時） | — | 螢幕截圖（淺色／深色）、元件測試 |
| 載入中（首頁／切換類別） | 以骨架取代列表；篩選維持可點（連續切換由競態處理收斂）；不顯示舊類別的列 | — | 螢幕截圖、元件測試 |
| 載入更多中 | 既有列保留；「載入更多」停用並顯示 spinner 與「載入中…」；防連點 | — | 元件測試 |
| 載入更多失敗 | **保留既有列**，在列表底部顯示行內錯誤（`role="alert"`）＋「重試」；重試以同一游標再取一次；不跳 Toast | 「無法載入更多紀錄，請稍後再試。」 | 元件測試、螢幕截圖 |
| 空（尚無任何紀錄） | 類別＝全部且第一頁沒有資料 | 標題「尚無任何紀錄」＋「取消預約、改期或修改設定後，操作紀錄會出現在這裡。」 | 元件測試、螢幕截圖 |
| 空（此類別沒有紀錄） | 類別＝預約或設定且第一頁沒有資料 | 標題「此類別沒有紀錄」＋「切換到「全部」或其他類別看看。」 | 元件測試 |
| 錯誤（首頁／切換類別） | **不顯示部分資料**；顯示 error 提示＋「重試」（重新載入第一頁）；類別篩選仍可切換 | 「無法載入稽核紀錄，請稍後再試。」（泛用訊息，不洩漏資料庫內容） | 元件測試、螢幕截圖 |
| 停用 | 不適用（無停用狀態） | — | — |
| 權限不足 | 非店長無法進入：沿用 `app/admin/layout.tsx` 三層檢查（導向登入／MFA）；即使直接打資料層，RLS 對非店長回傳空結果。本頁不另外處理 | — | 既有 layout 測試；TASK-084 整合測試的權限矩陣 |
| 行動裝置版／窄視窗 | 後台以桌面為主（既有非目標）；只確認 768px 不破版（做法依選定變體，見決策紀錄） | — | 螢幕截圖 |

### 待釐清問題的定案（任務卡「未知事項」）

1. **載入更多失敗**：保留既有列、底部行內提示＋重試（不整頁報錯、不丟掉已看到的資料）。理由：已載入的紀錄仍然正確且有用；整頁錯誤會讓店長失去目前閱讀位置。首頁／切換類別失敗則依需求「不顯示部分資料」整區改為錯誤狀態。
2. **差異欄位在窄視窗的呈現**：依選定變體——A：表格外層橫向捲動（最小寬度 720px）、差異欄允許換行；B：單欄自然重排；C：差異預設只顯示第一項，展開才全部顯示。

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 開啟頁面 | 進入 `/admin/audit-log` | 載入「全部」第一頁（50 筆） | 錯誤狀態＋重試 |
| 切換類別 | 點全部／預約／設定 | **重置游標與已載入的列**，進入載入中，在資料庫端篩選；選取中的類別以 `aria-pressed`／`aria-selected` 標示 | 錯誤狀態＋重試（維持新選的類別） |
| 載入更多 | 點「載入更多」 | 以目前最後一筆的 `id` 為游標取下一頁，附加在列表尾端 | 底部行內錯誤＋重試，既有列保留 |
| 重試（錯誤狀態） | 點「重試」 | 以目前類別重新載入第一頁 | 再次進入錯誤狀態 |
| 重試（載入更多失敗） | 點「重試」 | 以同一游標重新取下一頁 | 再次顯示行內錯誤 |
| 競態 | 連續切換類別，或切換時有請求尚在途中 | 較慢的舊請求回來時**丟棄**，只採用最新一次請求的結果（以遞增的請求序號判斷；切換類別時也作廢進行中的「載入更多」） | — |

## 設計系統對照

- 用到的既有 design token：grey 全階（文字階層 grey.900／700／500、分隔線）、primary（選取中的類別、主要強調）、danger／danger.light（錯誤提示）、info.light（空狀態）、radius.sm／md、elevation1（面板，shadow-only）、type scale 12／13／14／18／24、字重 400／500／600／700、spacing scale（4 的倍數）。
- 用到的既有元件：Sidebar（新增一個導覽項目＋圖示）、Table（A／C）、Chip（A 篩選，既有 filled+primary／outlined）、Tabs（B 篩選，比照設計師編輯頁頁籤）、Select（C 篩選）、Button（outlined「載入更多」、「重試」）、Skeleton（載入中）、Alert（錯誤／空狀態）。
- 本畫面新做的元件：`AuditLogView`（頁面專用，非跨頁共用，不放入 `components/ui/`；比照 `WeekCalendar`／`DesignerFilterChips` 的做法）——由既有元件組成，不引入新 token；實作完成後登記回 `design-system.md` 的元件庫 inventory，並更新 Sidebar 列的圖示數量。

## 視覺驗收標準

- 文字在 1100px 以上桌面寬度與 768px 窄視窗都不被截斷或溢出。
- 主要資訊的層次：事件名稱（600）> 對象與差異（400，深灰）> 時間／空值「—」（弱化）；沒有所有欄位同字級同字重同顏色。
- 錯誤與空狀態明確呈現，且與「載入中」視覺上可區分。
- 淺色與深色模式皆通過（對比 ≥ 4.5:1）；色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。
- 一律以純文字渲染（React 文字節點），不使用 `dangerouslySetInnerHTML`；使用者可控字串（服務名稱、設計師名稱）以 `<bdi>` 隔離方向並允許長字串換行，不撐破版面。
- 對照 `ai/checklists/design-review-checklist.md` 逐項檢查。
