# 畫面規格

## Metadata

- 功能：設計師後台核心畫面（Epic 0 UI 設計系統 S5）
- 畫面：登入、預約列表／日曆、服務與營業時間設定（三個核心畫面＋共用導覽版型）
- 狀態：草稿

## 目的

讓唯一的設計師帳號在桌面／平板上，登入後能有效率地管理預約、服務項目與營業時間；
決定整體導覽版型與資訊架構（不含最終資料串接，那留給對應功能 Epic 實作）。

## 版面配置

- 主要區域：預約列表／日曆（核心工作區）、服務與營業時間設定表單
- 次要區域：導覽（側邊欄或頂欄，依變體而定）、登入表單
- 導覽：登入後固定可切換「預約」「服務設定」「營業時間」三個區塊，含登出
- 動作：登入、篩選/檢視預約、標記預約狀態、新增/編輯服務項目、設定營業時間

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 登入（預設） | 帳密輸入表單 | 帳號或密碼錯誤：「帳號或密碼錯誤，請再試一次。」（沿用 TASK-003 既有文案） | 螢幕截圖 |
| 預約列表（預設） | 顯示今日／近期預約，含顧客／服務／時段／狀態 | 若無預約：「目前沒有預約」 | 螢幕截圖 |
| 服務與營業時間設定（預設） | 服務項目清單＋營業時間表單 | 若無服務項目：「尚未新增服務項目」 | 螢幕截圖 |
| 權限不足 | 非管理者帳號嘗試訪問 | 導回登入頁（沿用 TASK-003 既有 `is_admin()` 邏輯，本階段僅做版面，不重做邏輯） | 不適用（沿用既有實作） |
| 行動裝置版 | 非本階段設計重點（見「假設」：主要情境為桌面／平板） | 不適用 | 不適用 |

（此階段聚焦桌面／平板版型決策，故省略「載入中」「錯誤」等資料層狀態的逐一 mockup，
留給對應功能 Epic 依實際 API 行為設計。）

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 登入 | 輸入帳密並送出 | 進入預約列表 | 帳密錯誤：顯示錯誤訊息，停留登入頁 |
| 切換導覽 | 點擊「預約」／「服務設定」／「營業時間」 | 切換主內容區 | 不適用 |
| 新增／編輯服務項目 | 點擊服務列表的「新增」或某列 | 開啟表單（Modal 或內嵌，依變體而定） | 驗證失敗：欄位下方顯示錯誤 |

## 設計系統對照

- 用到的既有 design token：primary（強調色／CTA）、grey 色階、semantic 色（success 標記已完成
  預約、warning 標記待確認、danger 錯誤提示）、type scale、spacing scale、radius.sm/md、
  elevation1/2 陰影（見 `ai/context/design-system.md` S3）。
- 用到的既有元件：Nav（側邊欄或頂欄的視覺語言延伸自既有 `components/ui/Nav.tsx`）、Table
  （預約列表）、Card（服務項目卡／統計摘要）、Button、TextField、Select、ConfirmDialog
  （刪除/取消預約確認）、Toast/Alert（操作結果提示）（見 S4 inventory）。
- 本畫面新做的元件：若選定側邊欄變體，`components/ui/Nav.tsx` 目前只支援頂欄 AppBar 版型，
  側邊欄（Sidebar）需要在「預約管理後台」Epic 實作時另外新增並登記回 S4 inventory；日曆格狀
  檢視（如選用）也不在目前 inventory，需一併評估是否新增。mockup 階段先如實標記缺口，不在
  決策前擅自發明。

## 視覺驗收標準

- 文字在桌面（1200px 上下）與平板（768px 上下）都不會被截斷。
- 主要動作（登入／篩選預約／新增服務）清楚明確，符合舒適密度（S2 選定變體 A）。
- 錯誤與空狀態明確呈現。
- 色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。
- 重複使用元件庫 inventory 裡的既有元件；本階段潛在新元件（側邊欄／日曆格狀檢視）已如實
  標記，不在 mockup 決策前擅自發明其視覺風格之外的東西。
