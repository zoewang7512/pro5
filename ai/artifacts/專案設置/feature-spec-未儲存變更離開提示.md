# 功能規格書

## Metadata

- 功能：後台表單「未儲存變更」離開提示（TASK-081）
- 負責人：使用者（人工核准者）；實作 Agent：Claude Code
- 狀態：人工已核准（2026-10-22，使用者）
- 風險等級：中（只影響前端互動，不碰資料與權限；但攔截導覽若做得不當，可能讓使用者「離不開頁面」）
- 上層 Epic／User Story：專案設置／UI 設計系統
- 來源：TASK-070 驗收時使用者提出「有存檔按鈕的頁面，修改後沒存檔離開應提示」，決定另開本卡

## 問題

後台有「儲存」按鈕的表單，店長填到一半後離開頁面（點側邊欄、點麵包屑、登出、關閉分頁、重新整理、按 Esc 或點背景關閉對話框），
**輸入的內容會直接消失，沒有任何警告**。整個後台目前沒有任何未儲存提示（`app/` 下沒有 `beforeunload` 或 dirty 追蹤）。

現況（已查證）：

- 三個表單已經會算「有沒有變更」（拿目前值跟最近一次儲存的值比）：`BookingPolicyForm`、`StoreSettingsForm`、`DesignerBasicInfoForm`；
  `AccountSettingsView` 的顯示名稱與登入 Email 區塊也各有 `hasNameChanges`／`hasEmailChanges`；`BusinessHoursForm` 沒有，需要新增。
- 後台所有站內導覽都是自家程式碼：側邊欄（`components/ui/Sidebar.tsx`，`next/link`）、設計師編輯頁麵包屑（`DesignerEditView.tsx`）、登出鈕。
- `DesignerEditView` 的頁籤用 `hidden` 保持面板掛載，所以**切頁籤不會丟輸入**。
- `ServiceFormDialog` 以 `<Dialog open onClose=…>` 開啟，點背景或按 Esc 會直接關閉，輸入遺失。
- Next.js 16 App Router 沒有官方的離開攔截 API。

## 使用者

- 店長（後台唯一使用者，桌面為主）。

## 目標

- 表單有未儲存的變更時，離開前先提示；沒有變更時完全不打擾。
- 提示一致、可重用：一個共用機制，各表單只需回報「目前有沒有變更」。
- 不新增第三方套件；不讓使用者離不開頁面。

## 非目標

- **瀏覽器「上一頁／下一頁」按鈕不攔截**（已決定）：攔截 `popstate` 會造成歷史紀錄錯位或「離不開頁面」。這是已知限制，須寫進驗證報告。
- 「儲存並離開」按鈕（已決定只提供兩顆按鈕）。
- 自動草稿儲存、跨分頁或跨重新整理還原輸入。
- 即時儲存的控制項：設計師「提供服務」開關、作品集上傳與刪除、請假日新增與移除、頭像上傳與移除、商店 Logo／封面上傳。
- 動作型對話框（不是「編輯後按儲存」）：預約詳情的改期、取消與標記完成、公休日新增、設計師停用的確認對話框。
- 顧客前台的預約表單（本卡只管後台）。
- 變更任何表單的儲存邏輯、驗證規則或資料層。

## 功能需求

提示：

- WHEN 使用者要離開的頁面或對話框含有未儲存變更 THE SYSTEM SHALL 顯示確認對話框，標題「有尚未儲存的變更」，內文說明離開後輸入的內容會消失，
  按鈕為「繼續編輯」與「放棄變更」兩顆（「放棄變更」用警示色，預設焦點與 Esc 都落在「繼續編輯」）。
- WHEN 使用者選「繼續編輯」或按 Esc THE SYSTEM SHALL 關閉提示、停留在原處，且表單的輸入內容與焦點狀態保持不變。
- WHEN 使用者選「放棄變更」THE SYSTEM SHALL 關閉提示並完成原本要做的離開動作（導覽到目標網址、登出、或關閉對話框）。
- WHEN 沒有未儲存變更 THE SYSTEM SHALL 不顯示任何提示，離開行為與現況完全相同。

dirty 判定：

- THE SYSTEM SHALL 以「目前輸入值」與「載入時或最近一次儲存成功的值」比對；改回原值視為沒有變更。
- WHEN 儲存成功 THE SYSTEM SHALL 立即視為沒有變更；WHEN 儲存失敗 THE SYSTEM SHALL 仍視為有變更。
- WHEN 頁面同時有多個獨立表單（帳號設定的顯示名稱與登入 Email）THE SYSTEM SHALL 只要任一個有變更就視為有未儲存變更。
- 新增設計師模式：WHEN 所有欄位都與空白初始值相同 THE SYSTEM SHALL 視為沒有變更（不可沿用現有「新增模式 hasChanges 恆為 true」的判定）。
- 設計師「專長標籤」輸入框中尚未按 Enter 的文字 THE SYSTEM SHALL 視為變更（假設 A2，見下）。

攔截的離開方式：

- WHEN 使用者點擊側邊欄導覽項目、設計師編輯頁麵包屑、或登出鈕，且有未儲存變更 THE SYSTEM SHALL 攔截並顯示提示。
- WHEN 使用者關閉分頁或重新整理，且有未儲存變更 THE SYSTEM SHALL 觸發瀏覽器 `beforeunload` 提示（文案由瀏覽器決定，無法自訂）；沒有變更時 SHALL NOT 註冊這個處理常式。
- WHEN 使用者在服務項目對話框點背景、按 Esc 或按「取消」，且有未儲存變更 THE SYSTEM SHALL 顯示提示；對話框處於儲存中（submitting）時維持現況（不可關閉）。
- WHEN 使用者按瀏覽器上一頁／下一頁 THE SYSTEM SHALL 維持現況（不攔截，已知限制）。
- WHEN 設計師基本資料「新增」成功後以 `router.replace` 跳到編輯頁 THE SYSTEM SHALL NOT 攔截（先標記為無變更再導覽）。
- WHEN 使用者切換設計師編輯頁的頁籤 THE SYSTEM SHALL 不顯示提示（輸入已被保留，假設 A3）。

不可讓使用者離不開頁面：

- THE SYSTEM SHALL 在元件卸載、儲存成功、或使用者選「放棄變更」時清除攔截狀態；「放棄變更」永遠可用，不依賴任何非同步結果。

## 資料與 API

- 輸入：各表單回報的布林值（是否有未儲存變更）；不傳遞或保存任何表單內容。
- 輸出：提示對話框、攔截後的導覽、`beforeunload` 提示。
- 驗證：不變更任何既有驗證。
- 錯誤：無新增後端互動，無新的錯誤情境。
- 架構方向（細節留給技術規劃）：在 `AdminShell` 層提供共用 context 與 hook（暫名 `useUnsavedChangesGuard(isDirty)`），
  `Sidebar`、麵包屑、登出鈕的點擊經由它判斷是否攔截；不新增第三方套件。

## 安全性與隱私

- 身分驗證／權限：不涉及，不碰資料層與 RLS。
- 敏感資料：機制只保存「是否有變更」的布林值，**不保存、不記錄任何表單內容**。
- 濫用情境：不適用；主要風險是可用性——攔截失效造成「離不開頁面」或「登出被卡住」，以「放棄變更永遠可用」與卸載時清除狀態緩解。
- 登出：有未儲存變更時登出同樣提示，避免登出本身丟掉輸入。

## 假設（未問使用者、請核准時特別確認）

- **A1 帳號設定的密碼區塊不納入**：三個密碼欄位不計入變更。理由：瀏覽器自動填入會造成誤報，且內容容易重打。「顯示名稱」與「登入 Email」納入。
- **A2 專長標籤輸入框中未按 Enter 的文字算變更**：它是使用者已輸入但未存的內容，現有 `hasChanges` 沒有涵蓋，需要補上。
- **A3 切頁籤不攔截**：因為 `hidden` 保持掛載，切頁籤不會丟輸入。這與任務卡原本把「切頁籤」列為候選攔截方式不同；
  改用「頁籤小圓點」是否值得，留給 mockup 階段比較。
- **A4 營業時間表單需新增 dirty 判定**：與載入時的每週設定比對（現有程式沒有 `hasChanges`）。
- **A5 設計師停用的確認對話框、預約改期等動作型對話框不納入**：它們不是「編輯後按儲存」。

## 已決定（使用者，2026-10-22）

1. 範圍：全部有儲存按鈕的表單，加服務項目對話框。
2. 攔截方式：自製攔截；**不攔截瀏覽器上一頁**。
3. 提示按鈕：兩顆（繼續編輯／放棄變更），不做「儲存並離開」。
4. 分支：**等多位設計師合併 master 之後，再從 master 開分支實作**（規格與 mockup 階段只是文件，不受影響）。

## 驗收標準

- 上列每個納入的表單：有變更時，點側邊欄、麵包屑、登出都會先提示；選「繼續編輯」後停留且輸入不變；選「放棄變更」後完成離開。
- 沒有變更時（包含改回原值、儲存成功後）完全不提示。
- 有變更時關閉分頁或重新整理會觸發瀏覽器提示；沒有變更時不註冊 `beforeunload`。
- `ServiceFormDialog` 有變更時點背景、按 Esc、按「取消」都先提示；沒變更直接關閉；儲存中不可關閉。
- 設計師「新增」成功後跳到編輯頁時不出現提示。
- 新增設計師模式下，所有欄位為空時視為沒有變更。
- 不新增 npm 依賴；不改動任何儲存邏輯、驗證或資料層；機制不保存任何表單內容。
- 已知限制（瀏覽器上一頁不攔截）寫入驗證報告。

## 驗證計畫

- 單元測試：共用機制（有／無變更的攔截決策、多表單任一有變更、卸載清除、`beforeunload` 只在有變更時註冊與移除）；
  各表單的 dirty 判定（改回原值、儲存成功、儲存失敗、新增模式、專長標籤輸入中、營業時間）；提示對話框元件（按鈕、預設焦點、Esc）。
- 整合測試：不涉及資料層，無新增。既有整合套件應全數回歸通過。
- E2E：專案沒有 E2E 框架，以 Browser 手動走查替代：每個納入的表單各走一次「改了→點側邊欄→繼續編輯／放棄變更」。
- 視覺：提示對話框（桌面、暗色與亮色）、`ServiceFormDialog` 上方疊加時的層級。
- 手動：關閉分頁與重新整理的 `beforeunload`（瀏覽器原生提示，自動化難以驗證，列為手動項目）；確認瀏覽器上一頁仍照常運作。
- 型別檢查／Lint／Build：`npx tsc --noEmit`、`npm run lint`、`npm run build`。
