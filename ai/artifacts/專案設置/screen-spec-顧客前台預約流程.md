# 畫面規格

## Metadata

- 功能：顧客前台預約流程（Epic 0 UI 設計系統 S5）
- 畫面：服務列表 → 選時段 → 填寫資訊 → 預約成功（一條流程、4 個步驟）
- 狀態：草稿

## 目的

讓未登入的顧客在行動裝置上，從瀏覽服務項目到完成預約，決定整體版型與資訊架構
（不含最終文案與真實資料串接，那留給「顧客預約流程」Epic 實作）。

## 版面配置

- 主要區域：服務項目卡片列表 → 可選時段（日期＋時間格） → 姓名／電話表單 → 預約成功確認卡
- 次要區域：頁首品牌／標題、步驟進度指示（依變體而定）、服務說明／備註
- 導覽：單向線性流程（可返回上一步修改）；完成後回到首頁或查詢預約
- 動作：選擇服務、選擇時段、填寫聯絡資訊、送出預約、（成功後）查看預約詳情

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設（服務列表） | 顯示啟用中的服務項目卡片，含名稱／時長／價格 | 若尚無啟用服務：「目前尚無可預約的服務項目」 | 螢幕截圖 |
| 選時段 | 顯示可選日期與時段格 | 若當日已無空檔：「這天已無空檔，請選擇其他日期」 | 螢幕截圖 |
| 填寫資訊 | 姓名／電話輸入，含驗證 | 電話格式錯誤：「電話格式不正確」 | 螢幕截圖 |
| 送出中（載入中） | 送出按鈕顯示 loading，避免重複送出 | 不適用 | 螢幕截圖 |
| 預約成功 | 顯示預約摘要（服務／時段／聯絡資訊）與確認訊息 | 不適用 | 螢幕截圖 |
| 錯誤 | 時段已被搶訂等衝突情況 | 「這個時段剛被預約走了，請重新選擇」 | 螢幕截圖 |
| 行動裝置版 | 整條流程皆以行動裝置為主要設計目標（見「假設」） | 不適用 | 螢幕截圖 |

（此階段不含「停用」「權限不足」狀態：顧客前台為未登入公開流程，無權限分級。）

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 選擇服務 | 點擊服務卡片 | 進入選時段步驟 | 服務已下架：導回列表並提示 |
| 選擇時段 | 點擊可選時段格 | 進入填寫資訊步驟 | 時段已被搶訂：停留並提示重選 |
| 送出預約 | 填完姓名／電話並點擊送出 | 顯示預約成功畫面 | 驗證失敗：欄位下方顯示錯誤訊息，不送出 |

## 設計系統對照

- 用到的既有 design token：primary（強調色／CTA）、grey 色階（文字／背景／分隔線）、
  semantic 色（danger 用於錯誤提示、success 用於成功確認）、type scale、spacing scale、
  radius.sm/md、elevation1/2 陰影（見 `ai/context/design-system.md` S3）。
- 用到的既有元件：Card（服務卡片／預約摘要卡）、Button（CTA／次要動作）、TextField（姓名／
  電話）、FormSection（表單欄位間距）、Alert（錯誤提示）（見 S4 inventory）。
- 本畫面新做的元件：若最終選定「分步精靈」變體，需要一個 Stepper／進度指示元件，S4 inventory
  目前沒有登記；決策確定版型後，於「顧客預約流程」Epic 實作時依既有風格新做並登記回
  inventory，這裡先在 mockup 階段標記此已知缺口，不在 mockup 決策前補做。

## 視覺驗收標準

- 文字在手機版（375–414px）不會被截斷。
- 主要動作（選擇服務／選時段／送出）清楚明確，符合舒適密度（S2 選定變體 A）。
- 錯誤與空狀態明確呈現。
- 色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。
- 重複使用元件庫 inventory 裡的既有元件；本階段唯一潛在新元件（Stepper）已如實標記，
  不在 mockup 決策前擅自發明其視覺風格之外的東西。
