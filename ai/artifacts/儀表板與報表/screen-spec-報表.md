# 畫面規格

## Metadata

- 功能：儀表板與報表（`ai/artifacts/儀表板與報表/feature-spec.md`「預約量與營收統計」「熱門服務排行」）
- 畫面：儀表板與報表（`/admin/reports`）
- 狀態：mockup 已選定（使用者 2026-10-24）：「儀表板」頁籤＝變體 B、「報表」頁籤＝變體 C，另加「匯出 Excel（.xlsx）」。定案檔案：[`mockups/reports-final-tabs.html`](mockups/reports-final-tabs.html)；內容區的細節以變體 B／C 檔案為準（A 的描述保留作追溯）。使用者 2026-10-24 回覆「照預設」，定案版與預設假設皆視為已確認。

## 目的

讓店長在月底、排班、調價前，快速回答「這段期間做了幾筆、賺了多少、哪個服務最受歡迎、哪位設計師最忙」。**唯讀**：沒有任何寫入動作、不匯出。

## 版面配置

- 頁首：只有標題「儀表板與報表」，**不放口徑說明句**（使用者 2026-10-24 指示移除）；數字的範圍改由各彙總數字的標籤與副標說明（「營收（已完成 N 筆）」「預估營收：待完成，未計入營收」「已取消：不計入預約量」）。下方「口徑」表僅供實作與測試對照，不顯示在頁面上。
- 頁籤：標題下方「儀表板｜報表」兩個頁籤（沿用設計師編輯頁的頁籤樣式；`role="tablist"`），**預設「儀表板」**。切換頁籤時，下方工具列、設計師篩選與已選期間**保持不變**，只換內容區。
- 工具列：
  - 粒度切換「日／週／月」（單選，預設「月」）。
  - 期間導覽：上一期 `‹`、目前期間文字、下一期 `›`、「回到本期」（已在本期時停用）。日顯示 `10/24（六）`、週顯示 `10/19（一）– 10/25（日）`、月顯示 `2026 年 10 月`。
- 設計師篩選：沿用預約週曆的頭像 Chip 列（「全部 · N」＋各設計師 Chip，N＝**目前期間**的預約量；多選；勾選的 Chip 加 ✓；有勾選時顯示「清除篩選」）。篩選只存在記憶體，切換期間時保留，重新整理重設為「全部」。
- 匯出按鈕：僅「報表」頁籤；工具列最右側，outline 樣式「↓ 匯出 Excel（.xlsx）」（次要動作，不與頁籤選取色搶焦點）。狀態：預設／匯出中（停用＋spinner＋「匯出中…」）／停用（沒有資料、載入中、錯誤）。結果以既有 Toast 呈現（成功「已匯出「<檔名>」」、失敗「匯出失敗，請稍後再試。」）。
- 內容區：
  - **儀表板頁籤（變體 B）**：營收主角摘要列（營收 36px 主數字；預約量、預估營收、已取消為次要）→ 預約量圖與營收圖並排（月視圖 x 軸每 5 日標一次；窄視窗上下堆疊）→ 橫條排行（橫條長度＝預約量）。
  - **報表頁籤（變體 C）**：彙總列（六個數字）→ 熱門服務排行表（含占比條）→ 逐日明細表（日粒度為逐小時；表頭固定、內容區可捲動、最後一列「合計」固定在底部；今天列底色標示並加「今天」標籤）。
  - 兩個頁籤共通：趨勢以「日」為單位（日粒度以「小時 10:00–19:00」），每個單位都要出現，沒資料者為 0；排行顯示期間內所有有預約的服務，不設上限，預約量為 0 的不列，已下架服務標示「已下架」。
- 導覽：Sidebar 新增「儀表板與報表」，**放在「預約」之後（第二項）**，手繪 SVG 圖示（比照 TASK-064 慣例）；`isNavItemActive` 既有規則已涵蓋。
- 不顯示：任何顧客姓名、電話、email（本頁只有彙總數字與服務名稱）。

## 口徑（全頁統一，與功能規格書一致）

| 項目 | 定義 |
|---|---|
| 預約量 | 狀態為 pending／confirmed／completed 的筆數；cancelled 不計入（另列「已取消」） |
| 營收 | completed 預約的 `price_at_booking` 加總 |
| 預估營收 | pending／confirmed 預約的 `price_at_booking` 加總 |
| 日期歸屬 | `start_at` 換算 Asia/Taipei |
| 圖表的兩種標記 | 已完成＝實心主色；待完成＝斜紋主色（**不只靠顏色區分**，色盲也看得懂） |

### 邊界情境

1. **有預約但全部已取消**：預約量 0、已取消 N。視為「有資料」，不顯示空狀態（店長需要看到取消數）；趨勢全部為 0，排行為空時排行區塊顯示「此期間沒有被預約的服務」。
2. **跨月週**：週的範圍跨月／跨年時，標題照實顯示（例如 `10/26（一）– 11/1（日）`）。
3. **未來期間**：可切換到未來；只會有待完成預約，營收為 0、預估營收有值。
4. **服務已下架**：仍列在排行，標示「已下架」；服務名稱以 `<bdi>` 隔離並允許換行。
5. **趨勢圖標籤擠不下**：月份（31 個單位）在窄寬度時只標每 5 日（1、5、10…）；hover／focus 的單位仍顯示完整日期。
6. **價格快照**：漸層染髮 10/23 起由 NT$3,000 調到 NT$3,200，mockup 資料中 10/23 以前的預約仍以 3,000 計，示範「改價不影響過去營收」。

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 開啟頁面 | 進入 `/admin/reports` | 載入「月・本月・全部」 | 錯誤狀態＋重試 |
| 切換粒度 | 點日／週／月 | 以**目前日期所在**的日／週／月重新載入；保留設計師篩選 | 錯誤狀態＋重試（維持新選的粒度） |
| 上一期／下一期 | 點 `‹`／`›` | 前後移一個單位（日±1 天、週±7 天、月±1 月） | 同上 |
| 回到本期 | 點「回到本期」 | 回到包含今天（台北）的日／週／月；已在本期時停用 | 同上 |
| 設計師篩選 | 點 Chip | 多選切換；空＝全部；彙總、趨勢、排行同步重算；選取以 `aria-pressed` 標示 | 同上 |
| 切換頁籤 | 點「儀表板」「報表」或用方向鍵 | 只換內容區；日／週／月、期間、設計師篩選保留；不重新查詢相同條件的資料（可共用同一份彙總結果） | — |
| 匯出 | 報表頁籤點「匯出 Excel（.xlsx）」 | 以目前畫面顯示的彙總結果產生 `.xlsx` 並下載；匯出中停用按鈕 | 失敗 Toast＋可重試；沒有資料時按鈕停用 |
| 檢視單位明細 | hover／focus 長條（僅儀表板頁籤） | 顯示該單位的日期（或時段）、預約量（完成／待完成）與營收；**不提供點擊鑽取** | — |
| 重試 | 錯誤狀態點「重試」 | 以目前期間與篩選重新載入 | 再次進入錯誤狀態 |
| 競態 | 連續切換期間／篩選 | 較慢的舊請求回來時**丟棄**，只採用最新請求（遞增請求序號，寫法比照 `AuditLogView`） | — |

## 設計系統對照

- 用到的既有 design token：grey 全階（文字階層、分隔、骨架）、primary（選取中的粒度／Chip、長條主色、營收數字 `primary.700`）、primary.50（斜紋底色、今天列底色）、danger／danger.light（錯誤提示）、info／info.light（空狀態）、radius.sm／md、elevation1（卡片、面板，shadow-only）、type scale 11／12／13／14／16／18／24／36、字重 400／500／600／700、spacing scale（4 的倍數）。
- 用到的既有元件：Sidebar（新增「儀表板與報表」項目＋圖示）、Tabs（頁籤，比照設計師編輯頁）、Chip（設計師篩選，沿用 `DesignerFilterChips`）、ToggleButtonGroup 樣式（日／週／月；`AdminDashboard` 的檢視切換已在用）、Card／Paper（彙總列、面板）、Table（排行、明細）、Skeleton、Alert（錯誤、空狀態）、Button（重試、回到本期、匯出，含 `loading`）、Toast（匯出結果，`ToastProvider`）。
- 本畫面新做的元件（**實作時依既有 token 製作，完成後登記回 `design-system.md` 元件庫 inventory**）：
  - `TrendBarChart`（純 CSS／SVG 堆疊長條圖；純展示元件，**不引入新的圖表套件**）：涵蓋預設、hover／focus 顯示明細、單位為 0、標籤稀疏化、載入中（由呼叫端換骨架）；已完成＝實心 `primary.500`、待完成＝斜紋（`primary.500`＋`primary.50`）；a11y：每個單位有 `aria-label`（日期＋預約量＋營收），並提供等價的資料表（螢幕閱讀器可讀）。**儀表板頁籤使用兩次**（預約量圖、營收圖，同一元件以 `metric` 區分）。報表頁籤不使用。
  - 其餘（彙總卡、排行列、橫條）屬頁面專用，由既有元件組成，不入庫（比照 `AuditLogView`／`WeekCalendar`）。
- 導覽圖示：新增「報表」手繪 SVG，登記到 Sidebar 列（圖示數量 9）。

## 視覺驗收標準

- 文字在 1100px 以上桌面寬度與 768px 窄視窗都不被截斷或溢出；數字（NT$、筆數）不換行、`tabular-nums` 對齊。
- 主要資訊的層次：營收／預約量 ＞ 預估營收／已取消 ＞ 說明文字；沒有所有數字同字級同字重同顏色。
- 圖表：已完成與待完成**不只靠顏色區分**（斜紋）；今天以粗體＋主色標籤標示；y 軸只標 3 個刻度；網格線為弱灰、基線為較深灰。
- 載入中、空、錯誤三種狀態在視覺上可明確區分。
- 淺色與深色模式皆通過（對比 ≥ 4.5:1；圖表標記對背景 ≥ 3:1）；色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。
- 一律純文字渲染（React 文字節點），不使用 `dangerouslySetInnerHTML`。
- 對照 `ai/checklists/design-review-checklist.md` 逐項檢查。
